Core Topics

1. Algorithm Analysis & Efficiency 2–4 marks

What is algorithm analysis?

Algorithm analysis studies how the resource requirements of an algorithm grow as input size n grows. The two major resources are:

  • Time complexity: how the number of basic operations grows with input size.
  • Space complexity: how much extra memory is required as input size grows.

Why not simply measure seconds?

  • Different machines have different speeds.
  • Implementation and compiler affect runtime.
  • We care about growth for large inputs.
  • Asymptotic analysis gives a machine-independent comparison.

Cases of analysis

Case Meaning Example
Best case Minimum work for an input of size n Linear search finds target at first position
Worst case Maximum work for an input of size n Linear search finds target at last position / absent
Average case Expected work over a defined input distribution Linear search under a uniform-position assumption
Exam answer: “Algorithm analysis determines the time and space resources required by an algorithm as a function of input size. Time complexity measures operation growth; space complexity measures memory growth.”
2. Asymptotic Notations — O, Ω, Θ, o, ω High priority

The core idea

Asymptotic notation describes the growth rate of a function while ignoring constant factors and lower-order terms.

Big-O: upper bound

f(n) = O(g(n)) if there exist constants c > 0 and n₀ such that:

0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀.

Interpretation: beyond some point, f does not grow faster than a constant multiple of g.

Big-Ω: lower bound

f(n) = Ω(g(n)) if there exist c > 0 and n₀ such that:

0 ≤ c·g(n) ≤ f(n) for all n ≥ n₀.

Big-Θ: tight bound

f(n) = Θ(g(n)) if there exist c₁,c₂ > 0 and n₀ such that:

0 ≤ c₁g(n) ≤ f(n) ≤ c₂g(n) for all n ≥ n₀.

Little-o and little-ω

  • f(n) = o(g(n)): f grows strictly slower than g.
  • f(n) = ω(g(n)): f grows strictly faster than g.
Notation Meaning Think
O(g) Upper bound “at most this order”
Ω(g) Lower bound “at least this order”
Θ(g) Tight bound “exact asymptotic order”
o(g) Strictly smaller growth ratio → 0
ω(g) Strictly larger growth ratio → ∞

Example: prove 3n² + 5n + 7 = O(n²)

For n ≥ 1, n ≤ n² and 1 ≤ n². Therefore:

3n² + 5n + 7 ≤ 3n² + 5n² + 7n² = 15n².

Choose c = 15 and n₀ = 1. Hence: 3n² + 5n + 7 = O(n²)

Example: Θ

For f(n)=4n²+2n+9 the dominant term is n². We can bound it above and below by constant multiples of n², so: f(n)=Θ(n²)

Common mistake: “O means exact complexity.” No. O is an upper asymptotic bound. Θ is the tight bound.
Likely 2-mark question: Define Big-O and Big-Ω with examples. Write the formal inequality and one simple example for each.
3. Growth of Functions Foundation

Common growth order

For large n, a useful ordering is:

1 < log n < √n < n < n log n < n² < n³ < 2ⁿ < n!

Rules for simplifying complexity

  • Drop constant multipliers: 7n → Θ(n).
  • Keep the dominant term: n²+n+1 → Θ(n²).
  • Nested loops usually multiply their iteration counts.
  • Sequential blocks usually add, then keep the dominant term.
  • Halving/doubling repeatedly usually produces log n.

Example 

for i = 1 to n
    for j = 1 to n
        constant work

There are approximately n×n operations, so complexity is Θ(n²) . 

i = n

while i > 1
    i = floor(i/2)

The number of halvings is Θ(log n), so complexity is Θ(log n) .

4. Recurrence Relations — What They Mean High priority

A recurrence relation expresses the running time of a recursive algorithm in terms of the running time on smaller inputs.

General divide-and-conquer form

T(n) = aT(n/b) + f(n)

  • a: number of recursive subproblems.
  • n/b: size of each subproblem.
  • f(n): work outside the recursive calls.

Examples

Algorithm Recurrence Result
Binary Search T(n)=T(n/2)+Θ(1) Θ(log n)
Merge Sort T(n)=2T(n/2)+Θ(n) Θ(n log n)
Balanced Quick Sort T(n)=2T(n/2)+Θ(n) Θ(n log n)
Worst Quick Sort T(n)=T(n−1)+Θ(n) Θ(n²)
Important: The recurrence is not the final complexity. You still have to solve it.
5. Solving Recurrences — Iteration, Recursion Tree, Substitution High priority

A. Iteration / expansion method

Repeatedly expand the recurrence until reaching the base case.

Example: T(n)=T(n/2)+1 

T(n) = T(n/2) + 1
     = T(n/4) + 1 + 1
     = T(n/8) + 3
     ...
     = T(n/2^k) + k

Stop when:

n/2ᵏ=1

Therefore:

2ᵏ=n

so:

k=log₂n

Therefore: T(n)=Θ(log n)

B. Recursion tree method

Draw the cost at each recursion level, add the cost per level, then multiply by the number of levels.

Merge Sort

T(n)=2T(n/2)+n

Level # subproblems Cost each Total
0 1 n n
1 2 n/2 n
2 4 n/4 n
... ... ... n
log₂n n 1 n

There are Θ(log n) levels, each costing Θ(n), so: Θ(n log n)

C. Substitution method

Usually consists of three steps:

  1. Guess the asymptotic bound.
  2. Assume it holds for smaller inputs.
  3. Substitute the assumption into the recurrence and prove the bound.

Example idea

For: T(n)=2T(n/2)+n guess: T(n)=O(n log n) . Assume: T(n/2)≤c(n/2)log(n/2) , substitute, simplify, and choose constants so the inequality holds.

Exam: If asked to solve a recurrence and no method is specified, state the method you are using and show enough expansion/algebra to justify the final bound.
6. Master Theorem Very high priority

Standard form

T(n)=aT(n/b)+f(n)

where:

  • a ≥ 1
  • b > 1

Compare: f(n) with: n^(log_b a)

Case 1 — recursion dominates

If: f(n)=O(n^(log_b a−ε)) for some ε>0:

T(n)=Θ(n^(log_b a))

Case 2 — same order

If: f(n)=Θ(n^(log_b a) log^k n) then:

T(n)=Θ(n^(log_b a) log^(k+1)n)

Case 3 — outside work dominates

If: f(n)=Ω(n^(log_b a+ε)) together with the regularity condition, then:

T(n)=Θ(f(n))

Example 1 — Merge Sort

T(n)=2T(n/2)+n

  • a=2
  • b=2
  • n^(log₂2)=n
  • f(n)=n
  • Case 2

Answer: Θ(n log n)

Example 2

T(n)=4T(n/2)+n

  • a=4
  • b=2
  • n^(log₂4)=n²
  • f(n)=n
  • Case 1

Answer: Θ(n²)

Example 3

T(n)=T(n/2)+n

  • a=1
  • b=2
  • n^(log₂1)=1
  • f(n)=n
  • Case 3

Answer: Θ(n)

Do not blindly use Master Theorem. It applies to recurrences matching the standard divide-and-conquer form. For example: T(n)=T(n−1)+n is not a direct Master Theorem case.
Previous paper: “Solve T(n)=2T(n/2)+n using Master Theorem” was a 4-mark style question. Write: a, b, f(n), n^(log_ba), case, final Θ result.
7. Disjoint Sets / Union-Find 2–4 marks

What is a disjoint-set data structure?

It maintains a collection of mutually disjoint sets. Every element belongs to exactly one set.

Three fundamental operations

Operation Purpose
Make-Set(x) Create a new set containing only x.
Find(x) Return the representative/root of the set containing x.
Union(x,y) Merge the sets containing x and y.

Example 

Initially:

{1} {2} {3} {4} {5}


Union(1,2):

{1,2} {3} {4} {5}


Union(3,4):

{1,2} {3,4} {5}


Union(2,3):

{1,2,3,4} {5}

Now: Find(4) returns the representative of the set containing 4, which is the same set as 1, 2 and 3.

Why is it used in algorithms?

It is particularly useful for detecting whether adding an edge would create a cycle while constructing a spanning tree. Kruskal's MST algorithm is the classic example.

Forest representation

Each set can be represented as a rooted tree. Each node points to a parent. The root is the representative.

Union by rank / size

When merging two trees, attach the smaller/shallower tree under the larger/deeper one. This prevents tall trees.

Path compression

During Find(x) , make nodes on the path point directly to the root. Future Find operations become much faster. 

Find(x):

    if parent[x] != x:
        parent[x] = Find(parent[x])

    return parent[x]

With both union by rank/size and path compression, the amortized cost is: O(α(n)) per operation, where α is the inverse Ackermann function.

Previous paper: “State two operations on Disjoint Sets and role.” Safest answer: list Make-Set, Find and Union, then explain any two if the wording says two.
8. Divide and Conquer — General Method 4 marks

Three stages

  1. Divide: split the problem into smaller subproblems.
  2. Conquer: solve each subproblem recursively.
  3. Combine: combine the subproblem solutions into the full solution.

Generic structure 

DivideAndConquer(problem):

    if problem is small:
        solve directly

    else:
        divide problem into subproblems

        solve each subproblem recursively

        combine their solutions

Classic examples

Algorithm Divide Conquer Combine
Binary Search Choose middle Search one half Almost none
Merge Sort Split array into halves Sort each half Merge sorted halves
Quick Sort Partition around pivot Sort left/right Usually implicit after partition

Advantages

  • Often reduces large problems into manageable subproblems.
  • Natural recursive structure.
  • Can enable efficient parallelization.

Disadvantages

  • Recursion adds overhead.
  • Unbalanced division can destroy efficiency.
  • Combine cost can be significant.
9. Binary Search 2–4 marks

Requirement

The array/list must be sorted .

Idea

Compare the target with the middle element. If target is smaller, discard the right half. If larger, discard the left half. Repeat.

Example

Array: [10,20,30,40,50,60,70,80,90] target = 70.

  1. Middle = 50 → 70 is larger → search right half.
  2. Middle of remaining region = 70 → found.

Pseudocode 

BinarySearch(A, low, high, x):

    while low <= high:

        mid = floor((low + high)/2)

        if A[mid] == x:
            return mid

        else if x < A[mid]:
            high = mid - 1

        else:
            low = mid + 1

    return NOT_FOUND

Complexity

Case Complexity
Best Θ(1)
Average Θ(log n)
Worst Θ(log n)
Recursive auxiliary space Θ(log n)
Iterative auxiliary space Θ(1)

Recurrence: T(n)=T(n/2)+Θ(1) → Θ(log n)

Common trap: Binary search is not valid on an unsorted ordinary array.
10. Merge Sort Very high priority

Idea

Repeatedly split the array into halves until each part has one element, then merge the sorted parts.

Example

Sort: [38,27,43,3,9,82,10] 

Split:

[38,27,43,3]   [9,82,10]


Continue:

[38,27] [43,3]   [9,82] [10]


Single elements:

[38] [27] [43] [3] [9] [82] [10]


Merge:

[27,38] [3,43] [9,82] [10]


Merge:

[3,27,38,43] [9,10,82]


Final:

[3,9,10,27,38,43,82]

Merge operation

Take the smallest front element from the two sorted subarrays and append it to the output. Continue until both are exhausted.

Recurrence

T(n)=2T(n/2)+Θ(n)

Two recursive calls + linear merge.

Master Theorem: Θ(n log n)

Complexity

Best Θ(n log n)
Average Θ(n log n)
Worst Θ(n log n)
Auxiliary space Θ(n)

Properties

  • Stable: yes, with the standard merge implementation.
  • In-place: standard array merge sort is not in-place.
  • Predictable: Θ(n log n) in all standard cases.
Likely questions: Write Merge Sort algorithm; trace it on an array; write recurrence; solve recurrence; state complexity; explain why merge takes Θ(n).
11. Quick Sort Extremely high priority

Core idea

Choose a pivot, partition the array so elements go to the appropriate side of the pivot, then recursively sort the two partitions.

General process

  1. Choose pivot.
  2. Partition array around pivot.
  3. Recursively quick-sort the left side.
  4. Recursively quick-sort the right side.

Partition — one common exam convention

If the question specifies a partition method, follow it. If it does not, state the convention you are using. The exact intermediate array can differ between Lomuto and Hoare partition schemes while the final sorted array remains the same.

Example using last element as pivot (Lomuto-style)

Array: [10,80,30,90,40,50,70] pivot = 70.

Elements ≤ 70 are moved left; elements > 70 move right. One valid first partition gives: 

[10,30,40,50,70,90,80]
             ^
           pivot

Now recursively sort: [10,30,40,50] and [90,80] .

Important for your paper: Your previous mid-sem specifically asked for the partition steps on: [10,80,30,90,40,50,70] Practice this exact array, but also understand the method so a different array is not a problem.

Complexity

Case Partition pattern Complexity
Best Balanced halves Θ(n log n)
Average Reasonably balanced on average Θ(n log n)
Worst One side has n−1, other has 0 Θ(n²)

Why worst case is n²

T(n)=T(n−1)+Θ(n)

Expand:

n+(n−1)+(n−2)+...+1 = Θ(n²)

Why best case is n log n

T(n)=2T(n/2)+Θ(n)

Master Theorem: Θ(n log n)

Space

Average recursion stack is typically O(log n) for balanced partitions; worst-case recursion depth can reach O(n).

How to avoid bad pivots

  • Randomized pivot selection.
  • Median-of-three style heuristics.
  • Other hybrid implementations.
6-mark answer structure: Definition → choose pivot → show every partition step → recursive subarrays → final sorted array → best/worst complexity.

13. How to Analyze Divide-and-Conquer Algorithms Theory

The standard checklist

  1. Identify the number of recursive calls a.
  2. Identify the size of each subproblem n/b.
  3. Calculate non-recursive work f(n).
  4. Write: T(n)=aT(n/b)+f(n)
  5. Solve using Master Theorem, recursion tree, iteration, or substitution as appropriate.

Examples

Algorithm Recurrence Result
Binary Search T(n)=T(n/2)+1 Θ(log n)
Merge Sort T(n)=2T(n/2)+n Θ(n log n)
Quick Sort best T(n)=2T(n/2)+n Θ(n log n)
Quick Sort worst T(n)=T(n−1)+n Θ(n²)
14. Common Mistakes That Lose Marks Read before exam
  • Writing O(n²) when the question asks for a tight bound and the correct answer is Θ(n²).
  • Forgetting the base case when solving a recurrence.
  • Using Master Theorem on a recurrence that does not fit its form.
  • For Merge Sort, forgetting the Θ(n) merge cost.
  • For Quick Sort, claiming worst case is always n². It is the worst-case bound, not every input.
  • For Binary Search, forgetting that the data must be sorted.
  • For Disjoint Sets, confusing Find with Union.
  • In Quick Sort, changing the pivot/partition convention halfway through the trace.
  • Giving only the final sorted array when the question explicitly asks for partition steps.
  • Writing only a complexity value for a 6-mark question without explaining the algorithm.
15. Selection Sort 2–4 marks

Core idea

Repeatedly find the minimum element from the unsorted part and put it at the beginning.

Algorithm 

SelectionSort(A, n):
    for i = 0 to n-2:
        min_idx = i
        for j = i+1 to n-1:
            if A[j] < A[min_idx]:
                min_idx = j
        swap(A[i], A[min_idx])

Example

Array: [64, 25, 12, 22, 11]

  • Pass 1: min is 11, swap with 64 → [11, 25, 12, 22, 64]
  • Pass 2: min is 12, swap with 25 → [11, 12, 25, 22, 64]
  • Pass 3: min is 22, swap with 25 → [11, 12, 22, 25, 64]
  • Pass 4: min is 25, swap with 25 (no change) → [11, 12, 22, 25, 64]

Complexity

Case Reason Complexity
Best Inner loop always runs regardless of sortedness Θ(n²)
Average Inner loop always runs Θ(n²)
Worst Inner loop always runs Θ(n²)

Auxiliary space is Θ(1) (In-place sorting). Standard selection sort is NOT stable.

16. Strassen's Matrix Multiplication High priority

Standard Matrix Multiplication

Multiplying two n×n matrices takes Θ(n³) time using the standard 3-nested-loop algorithm.

Simple Divide & Conquer

Divide matrices into 4 submatrices of size n/2 × n/2.
Recurrence: T(n) = 8T(n/2) + Θ(n²)
Master Theorem: Θ(n³), no improvement.

Strassen's Method

Strassen reduced the 8 recursive multiplications to 7 by using clever algebraic manipulations.

The recurrence becomes:

T(n) = 7T(n/2) + Θ(n²)

Complexity Analysis

  • a = 7
  • b = 2
  • f(n) = Θ(n²)
  • n^(log₂7) ≈ n^(2.81)

Since f(n) = O(n^(log₂7 - ε)), by Master Theorem Case 1, the complexity is:

Θ(n^(log₂7)) ≈ Θ(n^(2.81))

Exam note: Be prepared to write down the recurrence relation T(n) = 7T(n/2) + O(n²) and solve it using the Master Theorem. Knowing all 7 equations is usually not required unless strictly taught in class, but knowing the count of multiplications (7) vs additions (18) is key.

19. Properties of Asymptotic Notations High Priority (IPU Exam)

1. Transitivity

If f(n) = O(g(n)) and g(n) = O(h(n)), then f(n) = O(h(n)).

Applies to: O, Ω, Θ, o, ω.

2. Reflexivity

A function is always bounded by itself: f(n) = O(f(n)).

Applies to: O, Ω, Θ (but not to strictly less/greater o, ω).

3. Symmetry

If f(n) = Θ(g(n)), then g(n) = Θ(f(n)).

Applies to: Θ only.

4. Transpose Symmetry

If f(n) = O(g(n)), then g(n) = Ω(f(n)).

If f(n) = o(g(n)), then g(n) = ω(f(n)).

Likely Question: "Explain properties of asymptotic notations with examples." (Usually 4–6 marks). State the property and write one basic algebraic example (e.g. n is O(n²), n² is O(n³), so n is O(n³)).
20. Master Theorem (Subtract and Conquer) IPU Specific

Form

For recurrences of the form: T(n) = a T(n - b) + f(n)

Where a > 0, b > 0, and f(n) = O(n^k) where k >= 0.

The 3 Cases

  • Case 1: If a < 1, then T(n) = O(n^k)
  • Case 2: If a = 1, then T(n) = O(n^(k+1))
  • Case 3: If a > 1, then T(n) = O(a^(n/b) * n^k)

Example

T(n) = 2T(n - 1) + 1

  • a = 2, b = 1, f(n) = 1 (so k = 0)
  • Since a > 1 (Case 3), the complexity is O(2^n)

Note: This is exactly the recurrence for the worst-case of recursive Tower of Hanoi!

21. Finding Maximum and Minimum (MaxMin) Common IPU Concept

Problem

Find the maximum and minimum elements in an array of size n.

Standard Approach

Linearly scan the array. Requires 2n - 2 or 2n - 3 comparisons.

Divide and Conquer Approach

Divide the array into two halves. Recursively find (max, min) for both halves, then combine by comparing the two maximums and the two minimums.

MaxMin(A, low, high):
    if low == high: // 1 element
        return (A[low], A[low])
    if high == low + 1: // 2 elements
        if A[low] < A[high]: return (A[high], A[low])
        else: return (A[low], A[high])

    mid = floor((low + high) / 2)
    (max1, min1) = MaxMin(A, low, mid)
    (max2, min2) = MaxMin(A, mid + 1, high)

    return (max(max1, max2), min(min1, min2))

Recurrence and Complexity

Recurrence for the number of comparisons: T(n) = 2T(n/2) + 2

Solving this using the recursion tree or substitution gives exactly 3n/2 - 2 comparisons.

Why is it better? While asymptotic time complexity is still Θ(n), the constant factor (number of comparisons) is reduced from ~2n to ~1.5n, making it faster in practice.

22. Algorithm Definition & Characteristics High Priority Theory (IPU)

Definition

An algorithm is a finite set of unambiguous instructions that, if followed, accomplishes a particular task and produces an output.

Essential Characteristics of a Good Algorithm

  • Input: An algorithm has zero or more externally supplied inputs.
  • Output: An algorithm produces at least one output.
  • Definiteness: Each instruction must be clear and unambiguous (e.g., no division by zero or confusing statements).
  • Finiteness: The algorithm must terminate after a finite number of steps for all possible cases.
  • Effectiveness: Every instruction must be very basic and feasible enough to be carried out in principle by a person using paper and pencil.
Likely Question: "Define an algorithm. What are the essential characteristics of a good algorithm?" (Common 4-mark short question).
23. A Priori vs A Posteriori Analysis Common Comparison (IPU)

Overview

When analyzing algorithms, we can measure performance theoretically (before running) or practically (after running).

Feature A Priori Analysis A Posteriori Analysis
Definition Theoretical analysis of an algorithm. Practical/empirical analysis of an algorithm.
When it is done Before implementation. After implementation and execution.
What it measures Time and space complexity using asymptotic notations (O, Θ, Ω). Actual time taken (in seconds/milliseconds) and bytes of memory consumed.
Hardware/Software Dependency Independent of hardware, compiler, or programming language. Highly dependent on processor speed, compiler optimization, and system load.
Result form Mathematical function (e.g., f(n) = n²). Exact statistical values (e.g., 2.3 seconds).
24. Time vs Space Complexity & Auxiliary Space Core Theory (IPU)

Time Complexity

The total amount of time required by an algorithm to complete its execution as a function of the length of the input (n). It is not measured in seconds, but in the number of basic operations (comparisons, assignments, arithmetic operations) executed.

Space Complexity

The total amount of memory space required by the algorithm during its execution. It is the sum of two components:

  • Fixed Part: Space needed for instructions, simple variables, fixed-size component variables, and constants.
  • Variable Part (Auxiliary Space): Extra space required dynamically based on the input size n, such as recursion stack space or dynamically allocated arrays.
Space Complexity vs Auxiliary Space:
Auxiliary space is the extra or temporary space used by the algorithm (excluding input data space). Space complexity includes both the auxiliary space AND the space used by the input.

For example, if an algorithm sorts an array of size n in-place, its Auxiliary Space is O(1), but its total Space Complexity is O(n) because of the input array itself. When analyzing algorithms, we generally care most about the Auxiliary Space.

Exam Mode — What to Write

2-mark: Big-O + Big-Ω

Big-O: f(n)=O(g(n)) if there exist c>0 and n₀ such that 0≤f(n)≤cg(n) for all n≥n₀. Example: 3n+2=O(n).

Big-Ω: f(n)=Ω(g(n)) if there exist c>0 and n₀ such that 0≤cg(n)≤f(n) for all n≥n₀. Example: 3n+2=Ω(n).

2-mark: Merge Sort recurrence

Merge Sort divides into two subarrays of n/2 and spends Θ(n) merging:

T(n)=2T(n/2)+Θ(n)
